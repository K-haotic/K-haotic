AI Systems Circuit · Research lab

The model is the engine.
The system is the circuit.

This is the research thread behind the AI Systems Circuit: how context shapes a model, how candidate answers meet a map of sources and constraints, and how hidden state can change what the visible interface seems to show.

Start with the circuit ↓

01 · Engine and circuit

One model. Many arrangements.

The model

The trained model produces a continuation from the input it receives. It contributes the generative engine and its learned parameters.

The arrangement

A product can add system instructions, conversation history, retrieval, tools, routing, usage controls, external services, and records. Those pieces determine what goes in, what happens between model calls, and what comes back out.

person / task
     ↓
instructions + session context + retrieved sources
     ↓
model proposes a result
     ↓
harness may route a tool call and receive its result
     ↓
response, action, or retained working record

The output alone does not show every step in its path. To explain a behavior, identify the parts of the circuit that could have produced it.

02 · Context and burn-in

A working session gathers shape.

A cold start begins without the task-specific history. Repeated examples, agreed terms, corrections, and objectives can make a session behave like a more specialized collaborator. Khaotic calls this process burn-in.

Burn-in changes the active context and therefore the conditions of the next answer. It is not the same as changing the trained weights. Context can also get crowded: old errors may be repeated, or the useful definition may be buried under accumulated material.

Compare the two memory paths

Session path: add examples and corrections to the context, then ask again.

Persistent path: select a result, attach its source and revision, and retain it in a separate working record for later retrieval.

Training path: change model parameters through a distinct training or fine-tuning process. A saved note by itself does not do that.

03 · Interference and geometry

Dreamer proposes. Surveyor checks the map.

The dreamer

Generates possibilities, comparisons, and hypotheses. It explores what might fit the pattern.

The surveyor

Checks a candidate against explicit coordinates, source relationships, admissible transitions, constraints, and history.

Both are needed. A precise check can still validate the wrong thing if the map was specified badly. A creative proposal can still be outside the permitted route. Keep the proposal and the map visible so the disagreement can be examined.

04 · Flat text and typed source graphs

Follow the relationship, not just the wording.

A similarity match can locate a passage that mentions a term. It may not identify which source defines the term, which proof depends on that definition, or which implementation and observation correspond to it.

A source-anchored retrieval path

Question→exact term / identity
Definition→assumptions and proof status
Implementation→test, revision, observed result

Each arrow is a typed source relationship. If a link is missing, stale, or unresolved, keep that gap visible. A diagram can change its layout without changing the underlying source identities.

The experiment

Compare flat embedding retrieval with source-anchored typed traversal on the same corpus and questions, under equal token budgets. Measure answer accuracy, completeness, wrong-version definitions, skipped premises, and unsupported claims. The question is whether the explicit relationships improve retrieval; the result belongs to the experiment.

05 · Magician’s trick · projection and hidden state

The visible display may not be the whole mechanism.

A display is a projection of the system state. Different underlying states can look identical in the current view. If those states can lead to different next outcomes, the view has hidden a distinction that matters for prediction.

Reveal the hidden seam · synthetic example

Same screen, different next step

Both records display “ready”. One has source permission for the next transition; the other does not.

State A · source S-14

Display: ready

History: source edge present

Next transition: continue

State B · source S-29

Display: ready

History: source edge absent

Next transition: hold

The display alone cannot determine the next step. Revealing the source identity and history resolves the difference in this example. Whether more detail improves a real prediction is something to test against outcomes.

Khaotic calls this research lens the magician’s trick: inspect what a presentation shows, what it leaves out, and whether the omitted distinction changes the next decision or outcome. “Not shown” does not automatically mean “deleted” or “deliberately hidden”; the mechanism and history determine what the gap means.

06 · Owner-managed harness

Who controls the valves?

A model provider can supply candidate analysis while a separate harness controls which model is called, what context is sent, which tools are available, what results are retained, and what may enter persistent working state. Model output and system authority are different parts of the circuit.

model proposal
   ↓
owner-side source and constraint checks
   ↓
accept / revise / hold + attributed result
   ↓
owned working record
   ↓
later retrieval, replay, or separately chosen training

Distilling a useful interaction into an owned record means selecting a result, attaching provenance, checking it, and retaining it for future work. That is different from the session context and from changing model parameters.

07 · Persistent recursive body

The body comes first.

Khaotic’s research question reaches beyond a chat session: can a computational body develop useful capabilities while retaining its identity, history, evidence, responsibilities, and future choices?

A foundation model may assist the body. A neural network can become a specialist; a tool or GPU can perform a task. Those components can change. The research places continuity in the body’s persistent state and developmental history, not in one replaceable model.

LEVI is Khaotic’s embodiment experiment. It investigates a recursive body across computational and physical substrates, with history, context, evidence, lineage, and controlled action carried through development.

The public five-role map

The Five-Field Recursion Engine describes five distinct roles in an ordered cycle:

ϕ · emergence→τ · cadence→ψ · memory→χ · coherence→Λ · regulation→ϕ

This role map is public; the exact recurrence is not part of this classroom. The research asks how a body keeps its fields, history, and evidence coherent as components change, and what experiments could distinguish that design from an ordinary model wrapped in a chat interface.
