# LEVI / COMPARATIVE EXPERIMENT AND BENCHMARK PROGRAM
### Make the classification an outcome of experiments

[LEVI flagship](LEVI.md) · [Public progress ledger](LEVI_PROGRESS.md) · [Founder](../README.md) · [Evidence register](PROVENANCE.md)

> **Do not declare LEVI superior to AI systems in advance. Make independent comparisons hard enough that any real difference survives them.**

## 1 / What we are testing

LEVI is being developed around **constitutive five-field recurrence, retained history, accountable continuity, bounded adaptation, developmental specialization and physical embodiment**. Conventional labels such as LLM, AI agent, RSI system or AGI do not isolate the proposed mechanism.

The experimental question is:

**Which behaviors, under what constraints, are causally attributable to the recursive-body architecture rather than the underlying models, prompts, tools, task engineering or hardware budget?**

The target isn't a leaderboard badge. It is a **reproducible capability map** with resource, failure, identity and generalization measurements.

## 2 / Comparison groups and controls

| Condition | Role |
| --- | --- |
| **Stateless model** | A current inference model with no persistent tools/history beyond the task context. |
| **Model + memory** | Same or comparable model with a conventional external memory/retrieval system. |
| **Tool-using agent** | Existing planning/execution system with allowed tools and task state. |
| **Recurrent/adaptive controller** | Appropriate non-LLM recurrent, reinforcement-learning or classical adaptive baseline for controlled dynamical tasks. |
| **LEVI observational baseline** | LEVI with selected body mechanisms disabled in a source-controlled and permission-safe test fixture. |
| **LEVI declared body configuration** | Same task, interface, available models and resource budget with admitted body-law, history and relevant development components enabled. |

**Ablations matter:** disable or alter one mechanism at a time: retained history, five-field regulation, scar retention, organ proposal, viability guards, resource feedback, or generational migration. Do not claim a global mechanism caused an effect if the ablation cannot isolate it.

Comparisons require matched or explicitly normalized compute, context budgets, tool access, hardware, task time, sampling settings, input access and data leakage controls.

## 3 / Experimental families

| Family | Example experiment | Metrics |
| --- | --- | --- |
| **Task effects** | Reproducible build/repair, constrained planning and code/tool work. | Task correctness, effect completion, failure rate and human intervention. |
| **Long-horizon memory** | Learn a correction, wait, interrupt, migrate and revisit. | Retention, harmful forgetting, retrieval cost, correction reuse and error recurrence. |
| **Continuity** | Replace a model or software component, reboot or change approved hardware. | Preserved identity, lineage, state invariants, witness continuity, recovery time. |
| **Self-repair and adaptation** | Introduce controlled faults and present repair alternatives. | Detection, repair quality, unauthorized action count, observed benefit, rollback integrity. |
| **Developmental specialization** | Repeatedly require a subskill that may become a candidate organ. | Utility gain, transfer, resource cost, compatibility, persistence across generations. |
| **Physical and environmental work** | Admitted device sensing and bounded real or simulated actuation. | Sensor accuracy, control stability, physical effect, latency and recovery from disturbance. |
| **Multiple bodies** | Coordination across distinct identities, partially conflicting objectives and resource limits. | Coordination quality, identity isolation, provenance quality and resource fairness. |
| **Geometry / dynamics** | Controlled hybrid-system tasks, bifurcation, viability and event-response benchmarks. | State error, stability, admissibility, mode selection and sensitivity under perturbation. |
| **Thermodynamic/resource accounting** | Measured power, memory, CPU/GPU use and time under equivalent workloads. | Joules/task, watts, memory-hours, compute-seconds, cost per retained improvement. |
| **Human interaction** | User or operator sets constraints and corrects a failure. | Alignment with permitted objectives, clarity of refusal/counterproposal, audit and repair burden. |

If a measurement needs a new sensor, instrument or dataset, it belongs in the preregistered methods—not in the reported results.

## 4 / Suggested core metrics

For each trial record task success and confidence interval alongside a small set of interpretable metrics:

- **Effect completion:** verified intended external outcome divided by attempted outcomes, defined per task.
- **Retention:** fraction of previously learned validated corrections reused successfully on held-out follow-up tasks.
- **Identity continuity:** number and severity of violated declared invariants across migration/restart conditions.
- **Evidence completeness:** number of required action witnesses present and valid divided by number required by the test contract.
- **Recoverability:** time/steps until the system returns to a declared admissible state after an induced disturbance.
- **Adaptation benefit:** out-of-sample improvement versus the strongest matched baseline, including costs and negative controls.
- **Resource efficiency:** energy, wall-clock latency, GPU/CPU time, storage and memory per successful effect; declare sensor provenance.
- **Developmental transfer:** performance on new tasks requiring a previously learned mechanism without replaying the original training.
- **Safety and authority:** refused prohibited operations, unauthorized effects, and the fidelity of action explanations to observed traces.

These are **benchmark definitions to implement**. No current values are being claimed.

## 5 / The proof ladder before serious comparisons

1. **Conformance:** demonstrate the registered mathematical operator on numerical and selected physical execution paths.
2. **Native execution:** native CPU and GPU stages complete with preserved evidence.
3. **Stateful body:** memory, constraints, lineage and receipts persist across relevant interruptions.
4. **Developmental closure:** demonstrate an admitted N→N+1→N+2 self-hosted continuation.
5. **Functional organ proposal:** show a new bounded specialist component that improves held-out performance and remains compatible.
6. **Externally witnessed trials:** publish methods and non-confidential artifacts for replication by people not building the system.

A clean experiment does more for the classification than a confident name.

## 6 / Statistical and methodological commitments

- Preregister sample sizes, task splits, prompts, budgets and acceptance criteria.
- Preserve **negative controls** and explicit falsifiers.
- Report medians, variation, uncertainty and failure modes, not only the best run.
- Track cumulative human assistance and tool/model provider contributions.
- Use matched hardware budgets or report normalized comparisons.
- Separate **simulation**, **Linux/NVIDIA GPU execution**, **native LEVI execution** and **human-facing product deployment**.
- Keep physical experiments staged, authorized, reversible when possible and fully witnessed.
- Make failure traces available in a reviewed disclosure tier when they do not reveal secrets, hardware credentials or patent-sensitive source.
- Invite independent critics to design the strongest fair baselines.
